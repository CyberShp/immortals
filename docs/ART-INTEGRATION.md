## 显示与降级

地图逻辑尺寸 640×360。底图原样使用，图像像素 / 2 转为显示尺寸。Pixi 的纹理加载显式指定 resolution=1，避免 `@2x` 文件名引发第二次折半；renderer resolution 为 max(2, devicePixelRatio)，autoDensity 开启。≥1280px 视口的普通布局 canvas CSS 宽 640px；窄屏缩小，紧凑模式继续 object-fit: contain。

弟子画布高 96px，显示高 48 逻辑像素，脚底锚点 (40,94)，相对于 80×96 画布。这里的 48px 指画布高度，透明边缘不算人物实体。URL 参数 `?discipleHeight=24` 用于可读性对比，允许 16–96，无 UI 控件。

建筑根据 `src/render/layout.ts` 地块宽导出，锚点按源底边中心缩放；对齐地块底边中心。模拟 slot 坐标不再参与显示。未建造显示半透明预留框；在建显示 t1 半透明；升级保留当前档并显示 ⚒。建筑与弟子分层：所有建筑图及预留框之上绘制建筑/预留位标签，再绘制独立弟子层（弟子之间按脚底 y 排序），名字标签位于弟子之上。位置变化用 1.2s 线性插值；仅移动时 requestAnimationFrame，约 180ms 换步态。隐藏/老板键 pause 取消动画并落到终点，Pixi ticker 不常驻运行。

所有图像 URL 使用 BASE_URL。Pixi Assets 分项捕获加载失败：底图回退椭圆地面，建筑回退色块，弟子回退圆点，只警告一次。配饰 img onerror 回退 ◇。构建代码放在 `bundles/`，美术独占 `assets/`，便于全量美术 404 验收。`window.__mapReady` 在首次绘制后为 true，`__mapStats` 报告当前帧底图、建筑、弟子和降级数量。

已替换：地图底图、建筑 t1/t2、五种弟子姿势、十种特质配饰图标。
仍占位：弟子卡片头像及「占位」小字、事件弹窗「图标占位」。配饰暂不挂在地图弟子上。

## 比例冲突

规范要求「建筑门高约为弟子身高 1.6 倍」。实测原图门高：主殿门约 72px（原图 @2x 像素，y≈268–340），炼丹房门约 56px。按地块宽缩放后：主殿门约 51 @2x px = 25.5 逻辑 px（≈0.53× 弟子 48px），炼丹房门约 31 @2x px = 15.6 逻辑 px（≈0.33×）。要满足 1.6×（≈77 逻辑 px 门高），主殿须放大约 3.0×、炼丹房约 4.9×，远超地块；反之若保持地块，弟子需缩到约 16px 才满足。根源是底图仅 1280×720（风格指南建议 @2x 4800×3000，约 3.75×）。当前处理：建筑按地块宽缩放、弟子 48px，未硬凑，等待 Iris/Lore 决定（出高分辨率底图 / 放大地图+镜头 / 缩小弟子）。

药圃图（含后方小屋）按地块宽缩放后高约 116 逻辑 px，是地块高 63 的 1.85 倍，小屋会压在主殿台阶前；炼丹房图高约 105 逻辑 px，会遮住静修室地块前沿；主殿图顶部超出地图上沿约 3px。当前按指挥官要求「按地块宽度等比缩放、底边中心对齐」，未裁切、未硬凑。需 Iris 决定：药圃是否去掉小屋（底图已画了围栏，是否只需作物层），或调整地块。弟子置顶解决人物被建筑遮挡，建筑图自身的比例冲突仍待美术决策。

待 Lore：配饰挂载方案；药圃/静修室/炼丹房 maxLevel=1，所以 t2 图暂不会用到。显示层以 data/buildings.json 的 maxLevel 为准，不修改模拟数值。

## 体积与验证边界

`public/assets/` 总计 **793136 字节**（含 manifest，51 张 WebP），低于 5,000,000 字节。运行导出后若新增文件，以 manifest.totalBytes 与文件系统统计为准。

首屏实际加载量（浏览器实测，2026-10-29 12:0x，Chrome 无头，vite preview）：**1,047,024 字节 ≈ 1.0 MB**（< 5 MB）。其中 script 773,505、image 263,272（底图 111,276 + 10 张建筑地图版 + 5 张 96px 弟子 + 10 张配饰图标）、stylesheet 8,954、document 1,293。统计口径为页面 Resource Timing 的 decodedBodySize（Playwright response.body() 对 fetch 加载的图片返回 0 字节，不可用）。dist 目录总量 1,576,943 字节，可作为上限。首屏不加载原尺寸大图。

浏览器复验结果（由外部在沙箱外运行）：`node scripts/e2e.mjs` 通过，原有 01–06 截图与交互断言通过，并新增 08 主界面、09 紧凑模式、10 48px canvas 原尺寸、11 聚集区局部 3× 放大、12 24px 对比。10/11/12 推进到第 60 步，姿势分布：行走 2、劳作 2、社交 1、打坐 1。404 降级：拦截全部 `/assets/**` 后无 pageerror，fallbacks=9，存档与事件弹窗仍可操作。短 soak（67 步）通过、无错误。紧凑模式截图前等待 800ms：立即截图会拍到 canvas 尚未重绘的旧画面（DOM 布局本身正确）。

无浏览器的地图调度测试还覆盖纹理 resolution、48/24px 比例、补间、暂停落点/恢复、隐藏时停帧及全图加载失败。这些测试使用 Pixi mock，不证明实际 GPU 绘制结果。
